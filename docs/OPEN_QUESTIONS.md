## A 类：历史设计矛盾（已全部定案 ✅）

### Q1 组队卡的筛选维度与字段对不上 ✅

- **结论**：筛选维度定为 **竞赛 / 招募方向 / 目标 / 发布日期**，全部有结构化字段支撑；技能标签只做展示不做筛选。已实现。

### Q2 信誉分删了，但互评体系还在 ✅

- **结论**：广告牌模式下互评/Review 体系整体移除，无信誉分。TeamMember 为纯展示名单，无平台内成员关系。

### Q3 头像字段被删 ✅

- **结论**：确认不要头像，昵称首字母色块兜底。头像需要文件上传/存储/CDN，P3 再议。

### Q4 日历按「校区」筛选，但没有校区字段 ✅

- **结论**：删除校区筛选；日历按级别（国际/国家/省/校）筛选。不引入校区字段。

### Q5 仓库结构里 admin 注释过时 ✅

- **结论**：已修正。采集子系统移除后，后台定位为「竞赛编辑 / 纠错处理 / 版本回滚 / 举报 / 用户 / 公告 / 反馈」。

### Q6 `user_skills` 表保留，但失去了使用场景 ✅

- **结论**：保留 —— 服务于个人能力名片（`/u/:id`、队长信息展示），并为 P3 智能匹配预留数据积累。

### Q7 竞赛详情页「留言讨论」多态评论 ✅

- **结论**：已按多态落地：`Comment.targetType` = COMPETITION / POST / TEAM，含 `(targetType, targetId, createdAt)` 索引与楼中楼拍平（parentId 指根 + replyToId 记录真实对象）。

## B 类：需要用户拍板的设计问题（已拍板 ✅）

### Q8 ⭐ 组队卡上的「个人联系方式」怎么展示？ ✅

- **结论（2026-09-27 Issue 1）**：广告牌模式下联系方式（QQ/微信，至少一项）**按意愿解锁**：
  - 壳信息公开（状态/方向/人数/意愿计数）；
  - 招募正文（要求、成员名单、队长信息）登录可见；
  - **联系方式仅队长 / 管理员 / 已登记「我想组队」意愿者可见，服务端不下发**，不靠前端遮挡；
  - 游客不可见任何联系方式。

### Q9 `isLocked` 人工锁定机制 ✅（语义保留）

- **结论**：`CompetitionEvent.isLocked` 保留在 V2 模型上（人工修改过的节点自动加锁，后台编辑提示「不会被自动更新覆盖」）。采集子系统整体移除后，该字段为将来的自动同步预留。

### Q10 学号解析规则 ⏳ 仍待确认

- **待确认**：`2024080909015` 中间位的学院编码规则；解析失败不能阻塞注册。
- **现状**：注册后资料补全页手动选择学院/年级，未做自动解析。

### Q11 学号位数是否统一？ ✅ 已定案（8–16 位纯数字）

- **结论**：登录/注册校验统一为 `/^\d{8,16}@std\.uestc\.edu\.cn$/`（前后端一致），即 **8–16 位纯数字 + 校园邮箱后缀**，不强制 13 位——本科生 13 位、研究生其他位数均可。学号直接取邮箱 @ 前缀入库，年级解析（前 4 位年份）尽力而为、失败不阻塞注册。
- **剩余风险**：若研究生/留学生学号**超过 16 位、不足 8 位或含字母**，仍会被拒；拿到真实格式后需再放宽正则（前后端各一处 + 忘记密码输入框）。

## E 类：V2 时代遗留待办（2026-10-11 新增）

### E1 管理后台暂不支持维护赛道 / 阶段 ⏳

- **现状**：`CompetitionTrack` / `CompetitionStage` 由种子数据（`scripts/gen_competition_seed.py` → `competition-seed.json` → `seed.ts`）维护；后台只能编辑挂阶段上的时间节点。
- **影响**：新增赛道/阶段需要跑种子脚本，无法在线维护。
- **建议**：P2 在后台编辑页补赛道/阶段管理（含 `sequence` 排序与 `bonusTier` 口径）。

### E2 种子数据的时间节点大多「待定」 ⏳

- **现状**：70 项竞赛中仅部分关键 DDL 有确切时间（多数节点 startAt/endAt 留空，前端展示「待定」）。
- **建议**：随各赛事通知更新，人工在后台补节点；或 P2 恢复轻量「人工快填」工具。

### E3 仓库遗留的旧管线文件 🗑️

- **现状**：`apps/api/prisma/bonus-list.json`、`extract_bonus.py`、`data/competition-sites*.csv` 等已不被引用（由 `gen_competition_seed*.py` 接替），待统一清理。

### E4 多届次数据为空壳 ⏳

- **现状**：V2 模型支持 `code + year` 多届次与届次切换，但种子只有 2026 届；跨年维护流程（复制上届骨架 → 更新时间节点）尚未演练。
