## 2. 通用建模规则

### 规则 A：无赛道赛事（复杂度 低/中）
不建 `CompetitionTrack` 行；所有 `Stage.trackId = null`；`Competition.hasTracks = false`。

以 **数模（CUMCM）** 为例：

**Competition**：`code=CUMCM, year=2026, hasTracks=false, stageChain="报名→竞赛→评奖", format=TEAM, teamSizeMin=3, teamSizeMax=3`

**Stage**

| code | name | stageKind | sequence | bonusTier |
|---|---|---|---|---|
| `SIGNUP` | 报名 | CAMPUS | 1 | NONE |
| `CONTEST` | 竞赛 | NATIONAL | 2 | NATIONAL |
| `REVIEW` | 评奖 | NATIONAL | 3 | NATIONAL |

**Event**

| stage | nodeType | startAt | endAt | note |
|---|---|---|---|---|
| SIGNUP | SIGNUP_END | — | 2026-09-03 | 由学校统一报名 |
| CONTEST | CONTEST | 2026-09-10 18:00 | 2026-09-13 20:00 | 72 小时 |
| REVIEW | RESULT | 2026-11-01 | — | 赛区成绩 10 月起 |

### 规则 B：赛道级赛制（决策 5）
`format`/`teamSizeMin`/`teamSizeMax` 写在 `CompetitionTrack` 上；赛事级字段仅作兜底。

### 规则 C：共享 vs 专属阶段
同一阶段各赛道时间相同 → 建 1 条 `trackId=null` 的共享 Stage；时间不同 → 每个赛道各建 1 条。

## 4. 汇总统计

> 口径：**有赛道** = 复杂度「高/极高」（赛道赛程各不相同）；**无赛道** = 复杂度「低/中」（无赛道，或仅有"组别"且共用同一条赛程链，用共享 Stage + 自定义字段表达）。

| 维度 | 数量 |
|---|---|
| 竞赛总数 | 70（学科 56 + 文体 14） |
| **有赛道**（`hasTracks=true`） | **33** |
| **无赛道**（`hasTracks=false`） | **37** |
| 其中**两层树**（赛道→赛项） | 1（`MEICC`） |
| **极高**（赛道链完全独立） | 3（`C4`、`MEICC`、`CUBEC`） |
| **高**（多赛道 + 独立赛程） | 30 |
| **中**（组别，共用赛程链） | 16 |
| **低**（无赛道） | 21 |

### 阶段链分布

| 阶段链模式 | 代表赛事 |
|---|---|
| 校赛→省赛→国赛 | 创新大赛、外研社国才杯、大广赛、商业精英挑战赛… |
| 校赛→赛区测评→国赛 | 电子设计竞赛、光电设计竞赛 |
| 分区赛→总决赛（无校省赛） | 挑战杯、结构设计、华语辩论世界杯 |
| 各赛道独立链 | 中国高校计算机大赛、嵌入式、集创赛 |
| 国际链（注册→评审→Jamboree） | iGEM |
| 报名→竞赛→评奖 | 数模、学创杯 |

### 结论

1. **赛道是主要变量**：33/70 有赛道，其中 30 个的赛道**时间轴各不相同**，必须用 `CompetitionTrack` 独立承载，不能共享 Stage。
2. **阶段链必须数据化**：至少出现 6 种阶段链模式，枚举方案（现状）必然失败。
3. **两层树只占 1 个**（`MEICC`），但仍需支持——`parentId` 自引用成本极低，不必为此单开表。
4. **赛制下沉到赛道级是必要决策**：如 `C4` 的天梯赛（10 人队）与大数据挑战赛（1–3 人）赛制完全不同。
5. **无赛道赛事占多数（37/70）**：这些走"规则 A"即可，不需要任何 Track 行，模型不冗余。
6. **"组别"不等于"赛道"**：16 个赛事只有组别（如数学竞赛的数学类/非数学类），赛程链完全一致，用共享 Stage + 自定义字段即可，不必建 Track。
